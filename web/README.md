# Web 原型

当前实现：音频捕获、实时波形、稳定单音识别、简谱显示与 TXT 导出。入口为 `index.html`，页面逻辑在 `app.js`，音高算法在 `pitch.js`。

`coach.html` 是参考第三方程序“曲谱悬浮窗/教练模式”概念实现的自有节奏教练预览。它能导入本项目导出的 TXT 简谱，显示当前/下一个音符、未来时间线和进度；可按 BPM 自动走谱，或在等待模式下按空格/右箭头逐音前进。面板可在网页内拖动、隐藏、调透明度和大小；支持的浏览器可打开文档画中画小窗。它不发送系统按键，也不是 Windows WPF 始终置顶窗口；独占全屏游戏中不保证可见。解析与计时在 `coach-core.js`，页面交互在 `coach.js`。运行 `node --test web/coach-core.test.mjs` 可检查基础解析和计时（从仓库根目录运行）。

独立的 `morse.html` 是三位密码门解码台。它提供系统/应用共享音频、麦克风、本地文件输入与手动点划校对。音频由 `morse-capture-worklet.js` 按音频时钟采样，再由 `morse-spectrum.js` 计算频谱，不依赖后台页面的动画帧。界面与解码逻辑位于 `morse.css`、`morse-controls.css`、`morse.js`、`morse-detector.js`、`morse-game-cue.js` 和 `morse-codec.js`。2026-10-02 的现场测试中，用户报告自动识别成功；仍请以游戏内反馈核对每次结果。

识别采用三条本地路径：高频游戏提示音由 `morse-game-cue.js` 按实际节奏实时逐位显示，并在第二次完整播放一致时复核；常规单音由 `morse-detector.js` 跟踪；`morse-rolling.js` 保留最近 30 秒的多频段窗口做候选复核。单次滚动匹配只显示“候选节奏”，不显示猜测数字。真实录音回放中，第一段读出 `083`；第二段两次一致读出 `162`，但用户曾标注答案为 `435`，该差异尚未查明，不应视为正确识别 `435`。

页面上的“点划记录（候选）”显示实时检测到的点划组，例如 `----- / ---.. / ...--`；尚不能判断长短的脉冲以 `?` 标记。五个脉冲能可靠对应数字时立即填写一位，不能对应时保留 `?`，不把后续数字前移。第一次完整播放的结果会保留到第二次复核；两次不一致时会提示核对，不自动覆盖首轮结果。

排查未识别问题时，先开始监听，再点击“开始诊断录制”，播放完整的游戏提示音后点击“停止并下载诊断”。页面会下载同名 `.webm`（部分浏览器为 `.ogg`）音频和 `.json` 识别日志；最长录制 2 分钟，仅保存在本机，不自动上传。录音可能包含麦克风语音，分享前请检查。

诊断录制入口默认隐藏（`window.dev === false`）。需要排查时，在加载页面前设置 `window.dev = true`，即可显示该入口。

在本目录运行 `python3 -m http.server 4173`，再访问 `http://localhost:4173`。浏览器需要授予麦克风或屏幕分享权限；系统/应用声音捕获取决于浏览器和操作系统支持。

曲谱管理和桌面桥接尚未实现，具体规划见 `../docs/architecture.md`。
