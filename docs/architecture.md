# Delta Force Audio：功能状态与技术架构

面向 PC 的浏览器音频监听与可视化原型。它可以通过浏览器捕获系统分享音频、麦克风或本地音频文件，并以实时波形展示输入状态。

现在还会对稳定的单音做实时音高识别，显示 C4 为 1 的简谱，并可导出 TXT。识别使用浏览器本地音频数据，不上传音频。适合清晰的单声部旋律；和弦、人声、噪声以及游戏混音可能产生误识别。导出 BPM 只是根据音符间隔估计，当前没有可靠的时值分析，建议导出后校对。

## 本地运行

```bash
cd web
python3 -m http.server 4173
```

打开 `http://localhost:4173`。捕获系统音频时，请在浏览器分享窗口中勾选“同时分享音频”。浏览器对桌面音频捕获的支持依系统和浏览器而异；如没有音轨，可使用麦克风或本地文件。

## 技术路线

项目采用“音频识别 / 曲谱输入 → 演奏调度 → 可替换输入后端”的分层架构：

1. **输入层**：支持浏览器系统音频、麦克风、本地音频和结构化曲谱。
2. **分析层**：完成音高检测、节拍估算、音符稳定化和简谱转换。
3. **映射层**：将标准音符转换为《三角洲行动》口琴键位，并生成带时间戳的演奏事件。
4. **调度层**：由 Windows 桌面客户端进行高精度计时，负责播放、暂停、变速、取消和按键释放。
5. **输出层**：通过统一的 `InputBackend` 接口提供多种实现：
   - `PreviewBackend`：只显示或播放预览，不产生系统输入；
   - `SendInputBackend`：使用 Windows `SendInput`，作为无需额外硬件的基础方案；
   - `SKSimulatorBackend`：接入 [scottfly189/SKSimulator](https://github.com/scottfly189/SKSimulator)，通过外接键鼠模拟器执行硬件级键盘和鼠标输入。

## 密码门摩斯识别架构

该功能与单音简谱识别共用音频输入，但使用独立分析管线，不将提示音转换为 MIDI：

```text
系统 / 游戏共享音频
        ↓
音频帧与频谱分析
        ↓
自动寻找连续、同频的候选提示音
        ↓
带通能量 + 动态噪声门
        ↓
提示音起止与持续时间检测
        ↓
短音“·” / 长音“—”分类
        ↓
五符号分组与数字解码
        ↓
独立网页解码台 / 规划中的 Windows 小窗
```

### 当前实现与后续优化

- 当前网页持续扫描窄带频谱，只有同频、间隔规律的五段提示音组成有效数字时才锁定其频率；单个稳定音调不会触发数字结果。
- 连续出现或消失数帧才切换提示音状态。五段时长与相邻间隔的比例用于短长音分类，时序不清楚时不输出数字。
- 诊断录音的主提示音约在 4.2 kHz，原先 3.0–3.5 kHz 的搜索上限将其排除。现用 AudioWorklet 按音频时钟采样、1024 点频谱以及独立的高频游戏节奏解析路径；常规摩斯时序解析和 30 秒滚动复核仍保留。真实录音回放读出第一段 `083`，用户也报告现场自动识别成功。第二段两次一致读出 `162`，但用户标注为 `435`，需确认录音与标注是否对应；不能硬编码已知答案或宣称该样本已通过。
- 游戏会将同一密码播放两次，两次之间约隔 2 秒。这个间隔是提示音片段的结构先验，不等于整条录音静音 2 秒（背景音仍持续）。后续可先识别重复片段、对齐并强化共同特征，再做点划分段；不可仅用全频音量的静音阈值切分。

## Windows 置顶小窗

纯浏览器页面不能可靠获得系统级始终置顶能力。桌面端计划使用 C# / .NET 8 与 WPF 提供独立显示层：

- 无边框透明窗口、始终置顶、拖动、缩放和位置记忆。
- 鼠标穿透开关以及显示、隐藏、重新识别的全局快捷键。
- 精简显示当前摩斯符号、解码数字、锁频状态和置信度。
- 与主程序共享识别状态，不在小窗内重复捕获或分析音频。
- 优先支持无边框窗口化游戏；独占全屏下不保证置顶显示。

桌面端与浏览器前端之间可使用本机 WebSocket 传递音频状态、符号和识别结果。连接中断时，小窗应明确显示离线状态并停止更新。

### SKSimulator 接入规划

- Windows 客户端使用 C# / .NET 8，与 SKSimulator 的 C# SDK 保持一致。
- 封装 `KMSimulatorService` 的初始化、设备搜索、打开、健康检查和关闭流程。
- 根据运行架构加载 `x64/skm.dll` 或 `x86/skm.dll`，设备 VID、PID 和校验数据放入本机配置，不写入曲谱。
- 将演奏事件映射到 `HKMKeyDown`、`HKMKeyUp` 和 `HKMKeyPress`；停止、异常退出或切换后端时必须释放所有按键。
- 设备调用集中在单一工作线程中，调度层通过队列顺序投递事件，避免并发访问硬件。
- 保留 `SendInputBackend` 和预览模式；未连接硬件、初始化失败或设备中途断开时停止演奏，不自动切换后端继续发送输入。
- 首次启用前提供按键测试、目标窗口确认和紧急停止热键，仅在用户主动启动且目标窗口匹配时输出。

SKSimulator 依赖专用硬件，并非纯软件方案。该后端只作为用户明确选择的可选能力，使用时需遵守游戏规则、设备条款及适用法律。
